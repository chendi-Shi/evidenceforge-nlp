# EvidenceForge 实验方法

项目研究一个明确问题：在固定科学论文摘要库中，词项匹配、冻结语义向量与有监督重排分别能解决哪些检索错误？交付物包括可复现实验、逐查询结果与本地检索 API；论文立场判断、证据句识别和答案生成不在当前任务内。

数据与许可细节见 [DATA_CARD.md](DATA_CARD.md)。特别注意：BEIR SciFact qrels 对应原始 cited 文档，相关性不等于论断支持关系。

## 1. 检索管线

```text
英文科学论断
  ├─ BM25 ───────────────┐
  └─ 冻结 MiniLM 编码 ──┤ 全语料排序 → RRF → top 50 候选
                        └──────────────────────┬─────────
                                               ↓
                                  查询-文档特征 → LambdaMART
                                               ↓
                                     排序后的候选论文摘要
```

数据只有 5,183 篇摘要，因此稠密检索采用精确向量打分。没有引入 ANN 的近似召回误差，也没有据此证明大规模服务能力。384 维 float32 文档向量本身约占 7.6 MiB，不包括文本、模型、稀疏索引与运行时开销。

### BM25：保留术语匹配信号

标题和摘要以换行连接，使用 Unicode 词边界分词和 `casefold`。当前配置为 `k1=1.2, b=0.75`，不做词干化或停用词删除。对于文档中的词项 `t`：

\[
\operatorname{IDF}(t)=\log\left(1+\frac{N-df_t+0.5}{df_t+0.5}\right)
\]

\[
s_{\text{BM25}}(q,d)=\sum_{t\in q}tf(t,q)\,\operatorname{IDF}(t)
\frac{tf(t,d)(k_1+1)}{tf(t,d)+k_1(1-b+b|d|/\overline{|d|})}
\]

这里 `t∈q` 遍历查询中的不同词项，查询重复词通过 `tf(t,q)` 加权。BM25 适合实体名、数值与专业术语，但无法仅凭词面匹配解决同义改写。

### Dense：复用冻结的句向量模型

使用 `sentence-transformers/all-MiniLM-L6-v2` 的固定 revision 和上游 `onnx/model_quint8_avx2.onnx` 量化权重，在 CPU 上推理。对 token 表征做 attention mask mean pooling，再 L2 归一化得到 384 维向量：

\[
e(x)=\frac{\operatorname{MeanPool}(h(x),m(x))}
{\|\operatorname{MeanPool}(h(x),m(x))\|_2},\qquad
s_{\text{dense}}(q,d)=e(q)^\top e(d)
\]

最大长度为 256 tokens，长摘要会被截断。本项目没有训练该 Transformer，也没有从 FP32 自行实施量化；“训练模型”特指后面的排序树。模型 revision、权重及 tokenizer 哈希进入实验元数据。上游结构与使用约定见 [MiniLM 模型卡](https://huggingface.co/sentence-transformers/all-MiniLM-L6-v2)。

### RRF：在排名空间融合

两路检索对全语料排序，以从 1 开始的排名计算：

\[
s_{\text{RRF}}(q,d)=\frac{1}{60+r_{\text{BM25}}(q,d)}+
\frac{1}{60+r_{\text{dense}}(q,d)}
\]

它避免直接把量纲不同的 BM25 分数与余弦分数相加，但会丢失原始分差，也不保证一定超过最强单路检索器。当前实现先融合全语料排名再取 top 50；它不同于先截断两路列表再融合的实现。公式来源于 [Cormack et al., SIGIR 2009](https://cormack.uwaterloo.ca/cormack/cormacksigir09-rrf.pdf)。

相同分数按文档 ID 的字典序打破平局。对词项完全缺失的查询，BM25 可能出现大量同分；平局处理必须可重复，且不能读取 qrels。

## 2. 监督重排与难负例

重排器是 LightGBM 的 `lambdarank` 目标配合梯度提升树，即 LambdaMART。样本是 `(query, candidate_document)`，每个 query 的候选形成一个 group；同一查询内部学习正例相对负例的次序。其排名梯度会按交换文档带来的 nDCG 变化加权，重点惩罚影响头部质量的次序错误。[算法说明](https://www.microsoft.com/en-us/research/publication/from-ranknet-to-lambdarank-to-lambdamart-an-overview/)、[LightGBM 参数文档](https://lightgbm.readthedocs.io/en/stable/Parameters.html#objective)

当前共有 16 个特征：2 个 BM25 特征（得分的 `log1p` 与倒数排名），3 个语义/融合特征（dense 得分、dense 倒数排名、RRF 得分），以及 11 个词面特征（查询词覆盖、文档词精确率、Jaccard、标题覆盖/精确率、二元词组覆盖、数字覆盖、否定词是否不一致、查询/文档长度、查询词在文档中的词频）。实际顺序以模型保存的 metadata 为准。文档 ID、query ID、qrels 是否命中均不作为特征。输出是用于排序的分数，不是经过校准的“证据可信度”。

训练候选由 RRF top 50 产生：

- qrels 中标为相关的候选为正例。
- 排名靠前但没有相关标注的候选作为难负例。这是操作性定义，不代表人工确认其不相关。
- 训练查询的相关文档未召回时，可以补入该正例，让学习器获得正负比较；实际注入数量应写入训练记录。
- **内部验证与 BEIR test 一律不补正例。** 否则会人为抬高候选召回率，掩盖第一阶段失败。

从冻结检索器产生候选，能避免负例来自一个曾使用验证或测试标签微调的模型。训练正例注入仍会改变训练样本分布；该偏差需要披露，并通过自然召回的验证/测试衡量端到端表现。

## 3. 划分、选择与最终评估

1. 读取官方 train 的 809 个查询。从它们的 qrels 建立“共享相关文档”的查询关系，同时连接小写、去标点和数字归一化后文本相同的查询；通过连通分量分组，相同组只能出现在内部训练或验证的一边。
2. 固定随机种子 `42`，按组划出约 20% 查询作内部验证，保存查询 ID 清单。组不能拆开，因此实际占比不一定恰好为 20%。该划分使用训练标签，不能描述为完全去污染。
3. 只用内部训练查询的候选训练重排器。当前预定网格为 `num_leaves ∈ {7,15}`，均使用 100 轮、学习率 0.05、`min_child_samples=20`、`reg_lambda=1`。按自然召回的内部验证 nDCG@10 选择，平局保留首个配置；当前没有早停。
4. 配置确定后，在全部官方 train 上重新训练。不能把内部验证指标称为这个全量重训模型的独立验证指标。
5. 使用同一固定语料库评估 BEIR test 的 300 个查询，输出完整实验表。保留所有 baseline，包括优于重排器的 baseline。

固定语料库中出现某篇测试相关文献并不自动构成标签泄漏；用测试 qrels 构造训练样本、选参数或补候选才会直接污染这个测试。冻结编码器本身的上游训练暴露是另一个问题，当前没有完成该审计。

重排方案的服务建议也在访问 test 前固定：仅当内部验证的学习重排高于 RRF 时建议学习重排，否则建议 RRF。这不是在五种方法中挑选测试分数最高者。公开 test 运行一次后就已经被观察；如果随后按 test 错例改特征、候选数或训练参数，需要记录这段开发历史，不能继续宣称它是从未使用的测试集。

## 4. 对照与消融

| 实验 | 要回答的问题 | 解释边界 |
| --- | --- | --- |
| BM25 | 单纯词面匹配能做到什么程度？ | 同一语料、同一标签；分词配置影响结果 |
| Dense | 冻结语义表征是否补充词面召回？ | 不代表本项目微调了编码器 |
| RRF | 两路排名融合是否改善排序或召回？ | 不能预设融合一定更好 |
| RRF + LambdaMART | 少量域内监督能否改善候选的头部排序？ | 只能重排已召回的文档 |
| 相同候选 + 词面特征重排 | 重排阶段的语义得分/排名特征贡献多大？ | 候选仍来自含 dense 的 RRF |

最后一项移除 `dense_score`、dense 排名和 RRF 等直接携带 dense 排名信息的特征，重新训练模型，而不是推理时将这些列置零。**它是重排特征消融，不是完全去掉 dense 的端到端系统。** 若要回答 dense 的总体贡献，还要增加纯 BM25 候选与纯词面重排的独立对照。

不预设 LambdaMART 优于 RRF 或 BM25。数据小、标签噪声、候选特征强相关、训练/验证分布差异均可能让复杂模型退化；报告负结果比挑选一条上涨指标更有信息量。

## 5. 指标与不确定性

所有指标先逐查询计算，再对同一批查询取宏平均。`rel_i` 是 qrels 给出的相关性；本数据为二值相关。

\[
DCG@k=\sum_{i=1}^k\frac{rel_i}{\log_2(i+1)},\qquad
nDCG@k=\frac{DCG@k}{IDCG@k}
\]

`IDCG` 由该查询全部已标注相关文档决定，不能只用召回候选中的正例计算。否则漏召回会被隐藏。

\[
MRR@10=\frac{1}{|Q|}\sum_q
\begin{cases}1/r_q,&r_q\leq10\\0,&\text{否则}\end{cases}
\]

\[
Recall@k(q)=\frac{|\operatorname{top}_k(q)\cap G_q|}{|G_q|}
\]

主指标为 nDCG@10；同时报告 MRR@10、Recall@10 和 Recall@50。MRR 只关心第一篇相关结果；Recall 检查是否漏掉其他已标注相关文献。

v0.2 起统一采用 TREC/BEIR 的原始相关度线性 gain。v0.1 实现使用指数 gain，但 SciFact 标签为二元，两者数值完全相同，已保存的 v0.1 结果不变；NFCorpus 的 1/2 分级标签使用上式。该修正在神经实验读取任何测试分数前完成，协议修订记录保留在结果目录。[TREC 官方实现](https://github.com/usnistgov/trec_eval/blob/master/m_ndcg_cut.c)

**候选上限。** 将 top 50 候选中全部相关文档理想地排在最前，仍使用全体相关文档的 `IDCG` 作分母，可得候选池内 oracle nDCG@10。它只用于诊断，不能用于线上排序或声称模型效果。若 RRF 与重排器都恰好返回同一批 50 个候选，Recall@50 应完全相同；重排无法找回池外文档。

**Bootstrap。** 当前报告的是方法差值的配对 bootstrap：对同一组查询索引有放回采样 2,000 次，计算宏平均指标差的分布，报告 95% 分位数区间，seed 为 42。主要比较各方法相对 RRF，以及全特征重排相对词面特征重排。两个独立区间是否重叠不等价于差异检验，且当前没有进行多重比较校正。

查询之间可能共享文献或近似论断，普通 query bootstrap 的独立样本假设并不完全成立，区间可能偏窄。它也不包含训练随机性、模型选择或领域迁移带来的不确定性，不能据此宣称普遍优越。

## 6. 可复现产物与复盘

按 [README](../README.md) 中的命令执行。默认实验目录为 `results/scifact`：

| 产物 | 复现用途 |
| --- | --- |
| `protocol.json` | 实验开始时写入的预定方法、指标、候选数与参数网格 |
| `frozen_models.json` | 测试评估前固定的模型哈希与验证集建议 |
| `report.json` | 汇总指标、配对区间、训练配置、环境、数据与代码哈希 |
| `per_query.jsonl` | 逐查询指标与候选上限 |
| `runs/*.trec` | 各方法的完整 top 50 排名、文档 ID 和分数 |
| `errors.json` | 自动归类的失败与退化样本，需人工进一步解释 |
| `model/`、`ablation_model/` | LightGBM 文本权重及特征、内部划分、训练记录 |

报告中的方法名为 `bm25`、`dense`、`rrf`、`learned` 和 `learned_no_dense`；CLI 中重排对应 `--method ltr`。只保存截图无法支持复现。

性能数据须标明 CPU、线程数、语料量、候选数、是否预热和统计边界。当前查询编码不缓存；文档编码可缓存。离线函数耗时不是 HTTP 并发压测结果，API 能在本地运行也不等于已生产部署。

错误分析优先按以下类型整理真实查询 ID 与文档 ID：

| 现象 | 首先检查 |
| --- | --- |
| 相关文档不在候选池 | 术语/缩写匹配、向量截断、两路互补性 |
| 候选已命中但排名靠后 | 特征有效性、难负例混淆、重排过拟合 |
| 高词面重叠但含义不同 | 否定、方向、实体或数值变化 |
| 人工阅读认为相关但 qrels 未标 | 标签覆盖；保留疑似漏标，不私自改 test 标签 |

后续优先增加跨种子或组级交叉验证、更大未观察数据上的迁移评估，以及长摘要分块对照。有明确计算预算后再做双塔或 cross-encoder 微调，并在相同候选、数据划分和指标下比较。这些是后续实验方向，不是当前已完成成果。
