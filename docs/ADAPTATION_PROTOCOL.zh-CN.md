# CPU 编码器适配：预先固定的实验协议与归因边界

本文记录本轮协议及代码审查事实，不报告尚未完成的训练或评测结果。完整主实验固定使用 **647 条内部训练查询、162 条内部验证查询、2 epochs、3 个采样组、seed=42**。现代 Qwen 模型的质量基线仍待吞吐测试与实际评测，不能据此宣称已经比较或超过它。

## 1. 本轮究竟训练什么

基础编码器为 `sentence-transformers/all-MiniLM-L6-v2` 的浮点权重，使用官方 `transformers.BertModel`、attention-mask mean pooling 和 L2 归一化。只在最后一个 Transformer block 的 attention query/value 线性层加入 LoRA，其余参数冻结。`rank=8, alpha=16` 对应 **12,288 个可训练参数**；这是实际编码器参数适配，不是仅更改检索权重，也不是生成式大模型微调。

固定配置：`max_length=128`、`batch_size=2`、每个查询 1 个标注正例和 2 个显式负例、AdamW `lr=0.001`、`weight_decay=0.01`、温度 `0.05`、梯度范数上限 `1.0`、CPU 2 threads。每组有 `ceil(647/2) × 2 = 648` 次计划更新，共 1,294 次查询曝光；最终完成步数、参数变化量和梯度记录以保存的训练报告为准。

对归一化向量的相似度 $s(q,d)=e(q)^\top e(d)$，每条查询的目标为：

$$
\mathcal L_q=-\log\frac{\exp(s(q,d^+)/\tau)}{\exp(s(q,d^+)/\tau)+\sum_{j=1}^{2}\exp(s(q,d_j^-)/\tau)}.
$$

没有 in-batch negatives。每条查询随机但确定地选择一个已知正例；其余已知正例不会成为该查询的显式负例。候选挖掘和三元组在训练前固定，两轮中不动态重挖，也不轮换正例。这使比较可检查，但限制了对多正例和大负例池训练的外推。

## 2. 三组处理与真正可识别的结论

| 组别 | 负例选择 | 保持一致的条件 |
| --- | --- | --- |
| `random` | 从完整语料随机采样，排除当前查询已知正例 | 查询、正例、初始化、更新次数、学习率、LoRA 结构、截断长度 |
| `retrieved` | 取冻结检索器 RRF top-50 中最靠前的非正例；不足时随机补足 | 同上 |
| `filtered` | 在相同候选池先做训练家族保护，再做教师分数过滤；从保留项取前 2 个，不足时随机补足 | 同上 |

这里控制的是更新预算，**没有匹配负例难度**；不同文档长度也可能带来不同 token 数和运行时间。`random` 对照回答“这个有限预算下，检索负例与随机负例的效果有何不同”。`filtered` 对照回答“联合过滤策略的效果如何”，不能单独证明假负例已经被纠正。

`filtered` 的两个操作必须分开解释：

1. **训练家族保护**：只用所选训练查询的标签，将共享正例文档或相同规范化 claim 的查询连成家族，排除家族中其他查询的正例。这些是“其他训练查询的已知正例”，并不自动成为当前查询的真阳性；连通性也可能把并不等价的查询连接起来。
2. **教师分数过滤**：默认使用冻结 MiniLM 的余弦相似度。对本次选择的正例分数 $s^+$，排除满足 $s^- \geq s^+ - 0.05$ 的未标注候选。高相似是潜在假负例的风险代理，也可能只是一个正确而困难的负例。低分正例会使规则更激进，可能移除大量困难候选并触发随机补足。

过滤后训练 loss 降低既可能来自冲突减少，也可能来自问题变简单。即使检索指标改善，仍只能归因于本轮联合采样策略；不能写“识别/修复了 X 个误标样本”或“去噪准确率 X%”。若使用外部教师分数，还必须记录教师权重、版本、分数尺度与覆盖率；无分数候选仍被保留，随机补足项也不能算作经教师确认的负例。

## 3. 数据隔离的范围

内部划分仅在 SciFact 官方 `train` 的 809 条查询内完成。通过共享正例文档、以及去标点/小写/数字归一化后的 claim 签名构建连通分组，seed 42 得到 647/162；两侧共享的已知正例文档和规范化签名均为 0。分组过程使用了这 809 条查询的标签，因此它是**基于标签构建的隔离划分**，不是完全不查看验证标签的随机切分。

训练候选的家族保护只使用 647 条训练查询；162 条验证查询只用于固定检索负例上的 InfoNCE 监测，不参加梯度更新，也不参与过滤。预先使用第 2 个 epoch 的最终模型；不按验证 loss 提前停止，不从测试分数挑选 epoch 或采样组，不进行 809 条查询的最终重训。三组最终模型都需要报告检索结果。

内部隔离不能推出官方 train/test 完全独立。只读审计发现：

- 官方测试查询 ID 与 647 条训练查询 ID 交集为 0。
- 测试 `1359、279、814、870` 与内部训练有相同规范化签名；`1292、13` 与内部验证有相同签名。数字归一化会合并数值变体，不等同于断言语义相同。
- 647 条训练查询和官方 test 的正例文档交集为 152 篇。此基准共享检索语料，不是文档互斥的泛化实验。

训练模块只读取 `qrels['train']`，上述 test 信息只用于审计，不能回流到采样或调参。标准主结果仍保留全部 300 条官方测试查询。排除重叠签名的分析若进行，应另标为事后敏感性诊断，不替换主指标。预训练编码器是否曾见过相关内容没有完整审计，不能声称彻底消除了所有预训练污染。

## 4. 不增加梯度预算的采样审计

运行保存计划的审计：

```bash
python scripts/audit_negative_mining.py \
  --plan path/to/training_plan.json \
  --data-dir data/scifact \
  --output path/to/negative_mining_audit.json
```

脚本只读取计划和可选的源数据 `qrels/train.tsv`，不加载模型、不训练、不读取目标域或测试标签。报告内容包括：

- 家族标记、教师标记、两者重叠及各自独占数。家族规则优先记录 decision；审计仍利用保存的分数独立重建教师标记，避免漏算重叠。
- `retrieved → filtered` 实际选中负例的替换率、查询改变率、随机补足数量。
- 三组**实际选中**负例的教师分数、相对正例分数差、原始 RRF rank 分布。旧计划若未保存原始 rank，只报告“排除当前查询正例后的候选池内 rank”，不能将二者混用。
- `family-only`、`teacher-only`、`combined` 三个影子规则的候选集合，及与 `retrieved` 的差异。这些集合不补随机项，空缺显式记录；它们没有训练对应模型，不能作为质量消融结果。

随机负例通常不在保存的 top-50 池里，其教师分数未知。脚本把它们计为未覆盖，绝不填成 0；随机组仅有分数的那部分具有选择偏差，不能直接代表完整随机组的难度。若要完整比较难度，应额外对三组实际选中的负例统一评分并记录成本。

现有计划不支持独立的“遮蔽正例”实验：它只保留一个 anchor 正例的教师分数，并已从候选中排除全部当前查询已知正例。脚本可统计多正例查询的可用规模，但将该审计明确标为 `not_run`，不伪造假负例检出率。后续可在多正例查询中固定 anchor，把另一正例从规则输入和家族保护中隐藏，单独计算被冻结规则过滤它的比例。即使这样，得到的也只是**已知正例上的筛除召回**，不是未标注候选上的假负例 precision；单正例查询无法同时提供独立 anchor 与被遮蔽正例。

若未来增加一次训练对照，最有价值的是“保留同样家族保护、匹配负例分数/排名与补足率、但不使用风险标记的采样组”。它有助于区分难度变化和风险规则的贡献。当前预先固定的三组主实验没有这一组，不能把它写成已完成消融。

## 5. 评测口径与迁移范围

主比较应使用**相同浮点基础模型、128-token 截断、归一化、完整语料**的未适配 baseline 与三个 LoRA 模型。此前 ONNX int8、256-token 的分数是另一配置，不应把量化或截断差异算成微调收益。密集检索与融合检索分别报告，候选深度与 RRF 参数固定；不要按 test 结果挑出获胜采样组后只报告它。

报告逐查询 nDCG@10、MRR@10、Recall@10/50、配对差值和区间。一个 seed 的查询 bootstrap 描述测试查询采样的不确定性，不能替代多训练 seed 的方差；相近 claim 也可能使逐查询独立重采样过于乐观。固定检索负例上的验证 InfoNCE 不是全语料检索质量指标。

迁移集采用完整 BEIR NFCorpus：3,633 篇文档，323 条 test 查询，12,334 条 test qrels；test 保留 1/2 两级相关度。其非技术健康问题到医学文献的检索，与 SciFact 科学 claim 检索存在任务和查询分布迁移，但主题仍有生物医学重叠。所有模型在 SciFact 上冻结后再评测 NFCorpus，不用后者 train/dev/test 标签训练、筛选阈值或选择模型。NFCorpus 相关度是检索标注，不是医疗事实、支持/反驳或安全性标签。

数据下载固定官方 MD5、archive SHA256、5 个数据文件 SHA256，并生成许可与统计 manifest。原作者允许学术用途，其他 NutritionFacts.org 数据用途需查看其服务条款并联系作者；项目代码许可不能替代数据许可。[NFCorpus 原作者说明](https://www.cl.uni-heidelberg.de/statnlpgroup/nfcorpus/)；[BEIR 官方数据列表](https://github.com/beir-cellar/beir#available-datasets)。

## 6. 相关研究与本项目的区别

- **RocketQA（Qu et al., NAACL 2021）**用训练好的 cross-encoder 对检索候选评分，只保留其高置信判为负的 hard negatives，再训练 dual encoder。它说明未标注正例可能污染难负例采样，但本项目的冻结余弦阈值不是其 cross-encoder 去噪流程，也未复现它的完整多阶段训练。[论文与 PDF](https://aclanthology.org/2021.naacl-main.466/)。
- **SimANS（Zhou et al., EMNLP 2022 Industry）**研究正例分数附近的模糊负例采样，试图兼顾信息量与潜在假负例风险。它并不证明所有高相似未标注项都为正例。本项目的硬阈值删选与其采样分布不同，只借鉴了“难度与误标风险需要一起研究”的动机。[论文与 PDF](https://aclanthology.org/2022.emnlp-industry.56/)。

可以声称完成的工作应由实际产物支撑：预先固定的对照协议、可重放的候选决策、真实梯度与权重变化、完整官方测试和迁移评测。检索提升、去噪有效性、强基线优势和生产部署都不能在测量前写成结论。
