# EvidenceForge 简历与面试准备

建议名称：**EvidenceForge：检索蒸馏、表示保持与迁移评测**。最新主线是 v3 的受控训练实验；v1 混合检索与 v2 LoRA 负例对照保留为问题来源和工程基础。数值版表述见[简历材料](RESUME.zh-CN.md)，完整数字见 [v3 结果](DISTILLATION_RESULTS.zh-CN.md)。只描述自己能运行、定位代码并解释取舍的工作。

## 60 秒介绍

> 我研究的是有限本地算力下，检索编码器适配新任务时的负迁移。我从固定 MS MARCO 来源抽取 12,000 条训练和 1,000 条验证查询，用冻结 Qwen3 Embedding 生成教师向量，训练 MiniLM 最后两层约 355 万参数。实验比较监督 CE、增加教师 KL、增加原始表示保持，以及两者组合，三个批次顺序种子共完成 12 组、9,000 次有效更新。模型只按源域验证选中，再评测完整 SCIDOCS。表示保持让 KD 的 nDCG@10 均值从 0.209372 提升到 0.215630，相对约 2.99%，但仍低于原模型 0.216406。因此结论是缓解这个配置下的负迁移。我同时保存全部对照、源域轨迹和权重身份，用独立脚本复算排名指标，避免把较弱对照上的改善写成普遍泛化提升。

## v3 高频追问

### 1. 这是知识蒸馏，还是只调用了一个大模型？

v3 有真正的教师到学生训练信号。教师 Qwen3-Embedding-0.6B Q8 权重冻结，输出离线向量；学生在同一候选集合上形成相似度分布，用 `KL(teacher || student)` 学习软排序关系，同时接受正例 CE 监督。另一个保持项约束学生接近原始 MiniLM 表示。Qwen 自身没有更新；MiniLM 是检索编码器训练，不是生成式大模型指令微调。

教师使用 512-token 上限，学生 256 tokens，tokenizer 也不同，效果不能单独归因于参数量。教师在 12,000 个固定三元组中有 4,458 次偏好标为负例的文档；这可能来自标签缺失、任务差异或教师错误，不能直接认定标注有误。[教师一致性记录](../results/distillation/teacher_label_agreement.json)

### 2. 目标函数和 batch 到底是什么？

总损失为 `L = CE + λKD × KL(pTeacher || pStudent) + λanchor × A`。四组的 `(λKD, λanchor)` 分别为 `(0,0)`、`(1,0)`、`(0,10)`、`(1,10)`；相似度温度固定 0.05，KL 没有额外乘温度平方。

每个 batch 有 16 条查询，每条提供一个主正例和一个固定 BM25 负例，组成最多 32 个共享候选。去除重复候选，并为每条查询屏蔽候选中的其他已知正例，避免把它们当作负例；CE 的目标仍是所选主正例，并非多正例求和目标。表示保持项为查询与唯一候选文档到原始模型向量的平均余弦距离，两部分各占一半。按长度拆微批只改变前向计算，恢复顺序后仍在完整候选池上计算损失。[训练实现](../src/evidenceforge/distill_student.py)

### 3. 为什么要四组，主比较和交互量分别回答什么？

`KD+anchor − KD` 是预设主比较，回答在这套蒸馏配置上添加表示保持是否改善目标任务表现。CE 和 anchor 两组用于判断保持项在普通监督训练中是否也有类似作用。次要交互量为 `(KD+anchor − KD) − (anchor − CE)`，不能用主差值代替。

主差值三种子均值为 +0.006258；交互量均值却为 −0.001340，各种子交互区间都跨 0。因此观察到“表示保持缓解 KD 退化”，没有建立它与蒸馏的特殊协同，更不能宣称新算法。[次要分析](../results/distillation/analysis.json)

### 4. 结果好在哪里？为什么不能说超过原模型？

SCIDOCS nDCG@10：base 0.216406；CE、KD、anchor、KD+anchor 三种子均值依次为 0.205354、0.209372、0.212952、0.215630。KD+anchor 相对 KD 约 +2.99%，但每个种子都低于 base。主比较正向与“适配后超过原模型”是不同命题；当前只支持前者。

四组源域验证较 base 的平均 nDCG 收益依次为 +0.035870、+0.023352、+0.038574、+0.011437，说明源域学习与目标域退化能够并存。源域分数来自抽样文档池，不是官方全库 MS MARCO 检索成绩。表示保持较强时也可能压低源域学习收益，不能仅展示目标任务一列。

### 5. 你测到了什么不确定性？

seed 17/42/73 使用相同数据、预训练初始化和关闭 dropout 的模型，主要改变批次顺序；同 seed 的四组共享顺序，形成配对对照。三个种子的标准差是描述性统计，不是置信区间，也没有覆盖数据抽样、初始化和全部训练随机性。

主差值的 95% 查询配对 bootstrap 区间依次为 `[0.003196, 0.011209]`、`[0.001048, 0.009643]`、`[0.002233, 0.010232]`，条件于各自已训练的两个模型。不能合并 seed×query 假装拥有 3,000 个独立查询；当前没有做查询家族聚类或多重比较校正。与 base 的区间跨 0 也不是等价性或非劣效证明。

### 6. 如何避免测试集参与选模？数据完全无泄漏吗？

先完整扫描固定来源的 502,931 行，再按规范化查询分组和全局哈希抽样固定 12,000/1,000 划分。源域验证与训练查询互斥，但共享 49 篇文档；它不是文档互斥验证，语义改写也可能跨组。已知正例只覆盖该三元组来源，并非完整 MS MARCO qrels。[数据审计](../results/distillation/data_manifest.json)

每组在 250/500/750 步验证，只按源域 nDCG@10 选择，平局取较早步；全部选中模型封存后才运行 SCIDOCS 目标评测。报告中源域训练查询与目标查询的规范化文本重叠列表为空，但这不证明语义无重叠，也没有审计上游预训练污染。代码和产物能检查流程一致性，不能把本地时间戳当成外部认证的历史证据。

### 7. `selected` 和 `final` 为什么可能不同？

12 组都训练到 750 步，`final` 保存最终步；`selected` 保存源域验证表现最好的已记录步。比如 KD+anchor 的 seed 17 选中第 500 步，而 seed 42/73 选中第 750 步。目标结果全部属于选中权重，不能用 final 替代后仍沿用原分数。

在 `results/distillation/training/<arm>/<seed>/selected/metadata.json` 和 `final/metadata.json` 中查 `filename` 与 `suffix_sha256`；`parameter_sha256` 是另一种参数内容身份。本地目录可保留旧候选，但公开产物仅包含当前 metadata 引用的 selected/final 权重，见[产物清单](../results/distillation/artifact_manifest.json)。[权重身份说明](DISTILLATION.zh-CN.md#选中权重与最终权重)

### 8. 表示漂移能证明为什么改善吗？

当前漂移是源域验证查询/文档对原始向量的余弦距离，没有测 SCIDOCS 漂移。KD+anchor 的源域漂移明显较小，与目标设计一致，但不同组可能选中不同训练步，早期 checkpoint 本身也可能漂移较小。分析保留同一组在 250/500/750 的完整轨迹供相同步数检查；关联不能直接证明目标域几何保持或收益机制。

### 9. 普通电脑如何完成？这是新的训练算法吗？

学生冻结 embeddings 和前四层，缓存其 FP32 hidden states，后两层的全部 3,548,928 个参数保留梯度；原始向量也缓存供保持项使用。关闭 dropout 后检查缓存与完整前向一致，长度分桶减少 padding，再恢复顺序计算共享损失。教师用本机 Iris Xe/Vulkan，学生用 CPU 两线程，顺序运行，无付费云算力。它是受限资源下的工程实现与实验比较，不是新的冻结层训练算法。

正式执行账本累计计费 15.5736 小时，按调用墙钟统计，排除预检、数据准备与调用间等待。一次关机以系统关闭时刻作保守上界，存在 115.74 秒不确定量；恢复时重算 44 步，不计入最终 9,000 步有效轨迹。不能把它写成独立认证的精确训练耗时。[账本](../results/distillation/execution_summary.json)

### 10. 独立审计到底证明了什么？

审计使用独立指标实现，从保存的 13 份 TREC 排名和本地 qrels 重算四项指标及每个 seed 的主差值区间；同时检查规范协议摘要、数据身份、12 组轨迹、验证选模与实际权重文件 SHA256。已保存结果为 `status=passed, ok=true`。[审计产物](../results/distillation/independent_audit.json)

它不重新推理、不重新训练、不检查张量数值，也不证明 top-50 之外的历史计算、计时真实性或注册时间真实性。`analysis.json` 则是读取 JSON 的次要分析，不等同于独立 TREC 审计。复查入口为 `python scripts/audit_distillation.py --check` 与 `python scripts/analyze_distillation_results.py`。

## v1/v2 历史工作怎样解释

### 11. v1 混合检索解决了什么？

BM25 保留术语、实体和数字匹配，冻结 MiniLM 提供语义信号；RRF 用 `1/(60+rank)` 融合全库两路排名，避免直接相加不同量纲分数。LambdaMART 对 RRF top-50 学习查询内排序，分数不能当作相关概率。SciFact 上 nDCG@10 从 RRF 0.6870 升到 0.7149，相对 +4.06%，配对差值区间 `[0.0117,0.0445]`。

同一批 50 个候选重排不会改变 Recall@50。移除 dense/RRF 特征的消融保留原候选池，检验的是重排特征贡献，不能称整个系统没有 dense。训练中可补入官方 train 正例，验证/测试不能补；这些成绩属于 ONNX INT8/256-token 的 v1，不属于 LoRA 或蒸馏。[v1 结果](RESULTS.zh-CN.md)

### 12. v2 的 LoRA 和负例过滤验证了什么？

v2 只在 MiniLM 最后层 Q/V 加 rank-8 LoRA，共 12,288 个参数；647/162 组级划分，每条查询一个正例和两个显式负例，**没有 in-batch negatives**。三组共享初始化、正例和更新预算，每组两轮 648 步，使用固定最终 epoch；验证 loss 仅监测，不据此早停。公平 baseline 是浮点 MiniLM/128 tokens。

过滤先保护同一训练家族已知正例，再排除满足 `s(负例) ≥ s(正例) − 0.05` 的候选，不足时随机补足。教师是冻结 MiniLM 风险评分，不是独立相关性真值；过滤同时改变难度与补足比例，因此不能说已证明“去噪”。SciFact、NFCorpus 的过滤组较未过滤检索组 nDCG 差值为 +0.1520、+0.1113，但相对 base，SciFact 区间跨 0，NFCorpus 下降。v2 暴露的退化问题促成 v3 对训练目标的研究。[v2 结果](ADAPTATION_RESULTS.zh-CN.md)

### 13. 检索相关等于支持论断吗？迁移等于完全不同领域吗？

不等于。BEIR SciFact qrels 对应 `cited_doc_ids`，其公开 test 对应原始 dev；339 个相关文档对中 130 个不在原始 evidence 字段。相关文献不能直接解释为支持或反驳，完整事实核验还需证据句与立场分类。官方 train/test 另有 6 个规范化 claim 签名重叠，不能声称完全无泄漏。[数据说明](DATA_CARD.md)

v2 的 NFCorpus（3,633 文档/323 查询）偏健康问题，与 SciFact 仍有生物医学主题重合；其 nDCG 使用线性 gain `rel`，MRR/Recall 以 `rel>0` 判断相关。v3 的 BEIR SCIDOCS 是 25,657 文档/1,000 查询的经典引用检索任务，不是整个原 SciDocs 套件，也不覆盖所有下游任务。

### 14. Qwen 基线、v3 教师与服务分别是什么？

v2 的冻结 Qwen Q8 基线在完整 SciFact 上实测 nDCG@10 0.6752，输入上限 128 tokens，包含查询指令和 EOS；v3 教师另用 512-token 配置，不能混用测时或成绩。Qwen 属于 2025 年发布的嵌入系列，不称全球最新，也没有做 Qwen LoRA。[固定资产与 v2 基线](MODERN_BASELINE.zh-CN.md)

FastAPI 是 v1/v2 本地检索演示接口；v3 当前重点是离线训练和可复算评测，不能自动宣称 v3 后两层权重已接入线上服务。数万文档采用精确全库向量排序，便于分离模型效果和 ANN 误差。扩大规模或生产部署还需测量索引误差、并发、更新与失败恢复；没有上线用户、线上 QPS 或业务收益的证据。

## 面试前做完四件事

1. 根据协议和 metadata，将基础模型、数据、选中权重、TREC 与报告对应起来；区分 `selected`、`final` 和恢复断点。
2. 手算小候选池的 CE、教师 KL、余弦保持项和配对差值；解释主比较、四组交互量与 frozen base 对照分别回答什么。
3. 解释源域提升与目标域退化并存、三种子与查询 bootstrap 的不同抽样单位，以及未知负例和预训练污染的限制。
4. 能定位训练、前缀缓存、微批重排、断点校验和独立指标实现。追加实验应另立假设与协议，不能把已经看过的目标结果反复用于选参后再当全新测试。
