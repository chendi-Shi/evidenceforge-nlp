# EvidenceForge 简历与面试准备

这份文档帮助解释已经实现并能复现的工作。简历只保留自己能运行、定位代码并解释取舍的内容；对外数字以[简历表述](RESUME.zh-CN.md)及其对应的完整实验报告为准，未运行的扩展不能写成已完成。

## 项目定位

**建议名称：EvidenceForge：科学文献检索、负例采样与神经适配。**

面向 NLP／大模型算法实习，可以将它放在信息检索、RAG 检索层或表示学习方向。v1 建立混合检索与 LambdaMART 排序基线；v2 在 MiniLM 上实际训练 LoRA，对比三种负例采样策略，并接入冻结的 Qwen3-Embedding-0.6B Q8 基线。项目没有进行 Qwen 权重训练、大模型指令微调或生成式答案训练，也没有事实核验分类器。

> 在 BEIR SciFact 300 条公开测试查询上，`[方法]` 的 nDCG@10 为 `[A]`，对比 `[明确基线]` 的 `[B]`，差值为 `[A−B]`；同时报告 Recall@50 `[C]` 和配对 bootstrap 差值区间 `[L,U]`。推理耗时 `[数值/单位]` 的测试条件为 `[CPU、线程、预热、计时范围]`。

`0.03` 的 nDCG 增益是 **3 个百分点**；相对提升为 `(A−B)/B×100%`，两者不可混写。若区间跨 0，可写“点估计提升，当前样本不能确认稳定优势”；若重排下降，就写对照发现与原因分析。不要把公开检索基准得分改称“业务准确率”，不要虚构用户量、线上 QPS 或生产收益。

v1 的实际例子是 RRF nDCG@10 `0.6870`、LambdaMART `0.7149`，相对提升 `4.06%`，配对差值 95% 区间 `[0.0117, 0.0445]`。这些数值属于 v1 的 ONNX INT8、256-token 检索配置与重排实验，不能写成 LoRA 或 Qwen 的收益。v2 的公平适配对照使用同一浮点 MiniLM、128 tokens；即使两份报告的指标名称相同，也不能把配置差异归因于训练。

## 60 秒介绍

> 我做的是科学文献检索，核心问题是有限算力下负例采样如何影响编码器适配。我先建立 BM25、MiniLM、RRF 和 LambdaMART 基线，再在 MiniLM 最后一层 Q/V 上训练 12,288 个 LoRA 参数。三组分别使用随机负例、检索难负例和风险过滤负例，固定相同的 647 条训练查询、初始化和每组 648 次更新。实验按训练内分组保留 162 条验证查询，预先固定最终 epoch，评测入口覆盖完整 SciFact 和 NFCorpus，并加入冻结 Qwen3 Embedding 对照。结果用实际报告中的主比较、置信区间和失败案例解释；过滤是否有效不能只看 loss，也不能把高相似候选直接叫作误标正例。

## 高频追问

### 1. 为什么要同时用 BM25 和 Dense？

科学术语、实体名和数字通常需要精确匹配；同义表达和句式变化需要语义表示。两类信号有可能互补，是否互补要看 Recall@50、各自独有命中的查询和融合效果，不能只展示一个好看的例子。Dense 也可能把“主题相近”当成“答案相关”。

### 2. RRF 解决了什么，为什么不直接加分？

BM25 和余弦分数量纲不同，直接相加会受分布支配。RRF 用 `1/(60+rank)` 将两路转换到排名空间后求和；代价是丢失分数间距。项目对全库两路排名融合再取 top 50，和只融合两个截断列表有区别。可以在内部验证上比较标准化加权融合，但目前没有证据说 RRF 在所有数据上最优。[RRF 原论文](https://cormack.uwaterloo.ca/cormack/cormacksigir09-rrf.pdf)

### 3. 你训练了什么模型？

v1 训练 LightGBM LambdaMART 排序树，监督来自官方训练 qrels；其 MiniLM 是冻结的上游 ONNX INT8 模型。v2 则加载官方浮点 MiniLM 权重，在第 6 个、也是最后一个 Transformer block 的 attention query/value 线性层加入 LoRA：`rank=8, alpha=16`，共 `2 × (384×8 + 8×384) = 12,288` 个可训练参数，其余参数冻结。三个组均完成 648 次更新，保存的 metadata 可检查完成步数、非零梯度和参数变化。Qwen3-Embedding-0.6B Q8 只做冻结推理基线。[训练实现](../src/evidenceforge/adaptation.py)与[固定协议](ADAPTATION_PROTOCOL.zh-CN.md)分别说明实际实现和归因边界。

### 4. LambdaMART 和普通二分类有什么区别？

最终目标是在同一查询下把相关文献排到前面。LambdaMART 按查询 group 构造排序学习信号，并让影响 nDCG 更大的次序错误获得更大权重；普通二分类通常逐条优化分类损失，未直接表达同一查询内的排序位置。必须保证 group 大小与连续样本顺序相符。预测分数只用于排序，不能直接解释为相关概率。[算法原理](https://www.microsoft.com/en-us/research/publication/from-ranknet-to-lambdarank-to-lambdamart-an-overview/)

### 5. 什么是难负例？会不会误伤正确文献？

`retrieved` 从冻结 RRF top-50 中选择未被当前查询标为相关的文献；`random` 从全库随机选，排除当前查询已知正例。`filtered` 先保护同一训练家族的已知正例，再排除冻结 MiniLM 余弦分数满足 `s(负例) ≥ s(选中正例) − 0.05` 的候选，随后从剩余项取两个，不足时随机补足。高相似度只是潜在假负例的风险代理，也可能是真正困难的负例。规则同时改变了负例难度和补足比例，不能把差值解释为“纠正误标”的单独因果效果，更不能声称去噪准确率。保存的[负例审计](../results/adaptation/negative_mining_audit.json)统计决策和替换情况，不提供未标注文档的真实相关性。

### 6. 为什么按共享文档分组？是否已经杜绝泄漏？

同一文献可能对应相近或相反表述的多个 claim。按 query 随机切分会让这类查询出现在内部训练和验证两边，因此仅在官方 train 的 809 条查询内，按共享相关文档或相同规范化 claim 的连通关系分组，v2 得到 647 条训练和 162 条验证查询。这个策略使用训练标签，也不能消除语义近重复、上游预训练暴露或官方 train/test 重叠。官方 train 与 test 有 6 条规范化 claim 重叠；主结果保留全部 300 条测试查询，排除这 6 条后的 294-query 分析须另标为事后敏感性诊断。数字归一化可能合并数值变体，不代表语义完全相同。

### 7. 训练时补正例不是作弊吗？

v1 对训练查询补入允许使用的标注正例，能让排序器学习有效正负对，但改变了训练候选分布，因此要记录注入量。v1 的验证和测试只能排序自然召回的候选。v2 的 InfoNCE 训练和验证 loss 使用固定的标注正例及两个显式负例，这是损失监测；最终检索质量评测让每条查询对完整语料排序，不向 top-50 结果注入正例。不能把已知正例一定在场的验证 loss 当作自然检索指标。

### 8. 为什么重排器无法提高 Recall@50？

如果输入输出都是同一批 50 篇文档，只改变顺序，集合没有变化，Recall@50 必须一致。重排可以改善 Recall@10、MRR@10 和 nDCG@10。如果目标文献在池外，需要改召回器、融合或候选数。候选 oracle nDCG 能衡量“在这批候选里，完美重排还能改善多少”。

### 9. 消融去掉了 dense，为什么仍保留 RRF 候选？

这项实验隔离的是**重排特征**贡献：使用相同候选，去掉 dense 分数、dense 排名和 RRF 等直接代理特征后重新训练。候选本身仍依赖 dense，因此不能称整个系统没有语义检索。完整去掉 dense 还需要独立比较 BM25 候选上的词面重排。

### 10. 怎样判断提升可信？

先看同一查询集合上的指标，再看逐查询变化及配对 bootstrap 的差值区间；不能只挑有利查询。v2 使用单个训练 seed=42，查询 bootstrap 反映查询抽样的不确定性，不能代替多训练 seed 的方差。相近 claim 可能相关，当前区间没有按家族聚类，也没有作多重比较校正。应先解释预先固定的主比较，随后描述其他对照与 NFCorpus 迁移；单次训练和两个公开基准不足以推出普遍优势。独立审计可重新计算 TREC 指标，但不会重放整个训练或证明所有上游数据没有污染。

### 11. 它真的在做事实核验吗？

当前做的是候选文献检索。通过对原始 SciFact 与 BEIR 发布包逐对比对，我发现 BEIR qrels 对应 `cited_doc_ids`，不只包含 `evidence` 文献：公开测试的 339 个相关文档对中，130 个不在原始 evidence 字段。甚至“相关文档”也不能直接解读为支持或反驳证据。完整核验还需要证据句选择和立场分类。[原始字段说明](https://github.com/allenai/scifact/blob/master/doc/data.md)、[本项目数据核验](DATA_CARD.md)

### 12. 只有 5,183 篇文档，凭什么有项目深度？

规模较小是实际边界。深度来自明确的问题和可审计的实验：真实公开标签、组级验证、实际编码器梯度更新、预算匹配的负例采样对照、完整语料检索、迁移评估和失败案例。v2 已实际完成三组 MiniLM LoRA 训练，可以讲清对比学习与参数适配；它仍不是大规模预训练、生成式大模型指令微调或生产系统。进一步的研究价值在于验证过滤机制，而不是增加组件名称。

### 13. 为什么不用 ANN、向量数据库或更多组件？

这个规模下可以精确计算全部向量分数，更容易分离模型效果与近似搜索误差。扩展至百万文档时，需要对比索引构建成本、内存、近似召回率和延迟，再决定 HNSW、IVF 等索引及服务存储。组件数量不是研究结论，未来扩展应由测量驱动。

### 14. 上线还缺哪些证据？

当前接口用于本地复现与演示。要用于真实产品，还需定义用户与语料更新场景、补充目标领域标注、评估分布漂移，并测量并发、冷启动、失败恢复和资源占用。没有完成的压测、鉴权或可用性工作不写成已上线成果。

### 15. InfoNCE 怎么构造，batch size 2 意味着几个负例？

查询和文档共用编码器，使用 attention-mask mean pooling 后 L2 归一化，以余弦相似度除以温度 `0.05` 得到 logits。每条查询固定一个标注正例和两个显式负例，计算三分类交叉熵，正例索引为 0。**没有 in-batch negatives**，因此不能声称通过 batch size 2 获得其他查询的负例。采样计划在梯度更新前固定，两轮不动态重挖；每组 647 条查询、batch size 2、2 epochs，共 `ceil(647/2) × 2 = 648` 次更新、1,294 次查询曝光。三组共享初始化、正例选择、查询顺序和优化配置，但没有匹配负例难度、token 总数或实际耗时。

### 16. 教师有多强？这是知识蒸馏吗？

当前过滤教师是与学生同源的冻结 MiniLM INT8、256-token 编码器；学生训练与公平 baseline 是浮点、128-token 配置。教师分数只用于构造负例风险规则，没有软标签 KL 损失，也没有强 cross-encoder 教师或 Qwen 蒸馏，因此不称为知识蒸馏。Qwen 可导出独立的官方 train-query 向量作为后续实验输入，但该导出不会替换已固定的三组采样计划。若要证明过滤真的识别假负例，需要独立相关性标签，并将难度、补足率等混杂因素纳入对照。

### 17. 为什么验证 loss 降低不一定提升检索？怎么选模型？

固定两负例的三分类任务与从几千篇文献里找相关项难度不同，loss 也受温度和负例分布影响。训练前已固定使用第 2 个 epoch 的最终权重；162 条内部验证查询只监测固定检索负例上的 InfoNCE，不早停、不按 test 挑 checkpoint，也不再用全部 809 条查询重训。报告完整四编码器结果，包括负结果。比较过滤机制时看 `filtered − retrieved`；比较适配效果时看各组与相同浮点、相同 128-token baseline 的差值。

### 18. NFCorpus 验证了什么？nDCG 的相关度怎么算？

NFCorpus 提供 3,633 篇文档、323 条 test 查询，查询偏非技术健康问题；SciFact 则是科学 claim。迁移评测让已在 SciFact 上固定的模型直接检索 NFCorpus 全库，不用后者 train/dev/test 标签更新参数、过滤阈值或选择模型。二者仍有生物医学主题重叠，应说任务与查询分布迁移，而不是完全无关领域泛化。NFCorpus 保留 1/2 两级相关度，nDCG 使用与 TREC 口径一致的**线性 gain `rel`**，不是 `2^rel − 1`；MRR 与 Recall 按 `rel > 0` 判断相关。NFCorpus 数据仅按原作者许可用于学术用途，项目代码许可不能覆盖数据许可。

### 19. 怎么在普通电脑上比较四个编码器？这是新的训练算法吗？

训练只更新最后层 Q/V 的 LoRA 参数，使用 CPU 两线程并顺序执行三组。评测时 `MultiAdapterEncoder` 对一批文本先运行完整未适配 baseline，保留倒数第二层 hidden states，再依次装载三个适配器并计算各自最后一层，复用公共前缀；这适用于基础模型和前五层完全相同、推理关闭 dropout 的四组模型。缓存按块保存最终向量，没有缓存全语料的中间 hidden states。它是**多适配器评测的共享前缀推理优化**，不能称为新的冻结层训练算法，也不意味着训练时跳过了前五层前向计算。跨断点恢复的训练 `elapsed_seconds` 仅覆盖该次调用，不是从零训练总时长。

### 20. Qwen 是最新模型吗？为什么只用 0.6B？

固定的是官方 Qwen3-Embedding-0.6B 的 `Q8_0` GGUF 权重和 llama.cpp 版本，属于 Qwen 2025 年发布的文本嵌入系列；“现代基线”不代表全球最新模型。0.6B 和量化配置适合这台 16GB 共享电脑的本地推理预算，不能从参数量直接推出质量。模型使用 last-token pooling、1,024 维输出和 L2 归一化；输入上限 128 tokens 包括查询指令及最终 EOS。它与 MiniLM 的 tokenizer 不同，相同 token 上限不代表覆盖相同文本。质量必须读取完整 SciFact 报告，16 篇摘要的 CPU/Vulkan 吞吐预检只说明本机运行表现。项目未训练 Qwen 权重，不能写“Qwen LoRA 微调”。[固定资产及运行口径](MODERN_BASELINE.zh-CN.md)。

### 21. 如何确认结果文件真的对应完整实验？

先核对协议、输入文件哈希和已冻结 adapter 哈希，再读取训练 metadata 的 `completed_steps`、非零梯度和参数变化。适配 `report.json` 会按数据集逐次更新，必须确认 `datasets` 与 `comparisons` 同时包含 `scifact`、`nfcorpus`，每个数据集均有 `base/random/retrieved/filtered`。然后用独立脚本从完整 TREC 排名重算四项指标，检查逐查询覆盖、排名与报告一致。Qwen 同样要求完整 5,183 篇语料、300 条测试查询及最终报告；进度文件和已下载权重都不是质量证据。点积排序耗时、缓存重跑耗时、16 文档吞吐投影和端到端在线延迟必须分别解释。

## 面试前做完四件事

1. 在干净环境按 README 复现一次，把数据哈希、模型 revision、参数与报告对应起来。
2. 手算一个两路 RRF 排名、一个带两级相关度的线性 nDCG@3、一个含两个负例的 InfoNCE，并解释重排前后 Recall@50 为何相同。
3. 从完整报告选取成功、退化和疑似漏标案例，带上 query/doc ID、原始文本及三个采样组的对应决策；明确哪些只是待验证的解释。
4. 能独立定位训练、共享前缀推理、指标与断点校验代码。若追加实验，先固定新假设与协议，再使用允许的训练/验证信息设计对照，不回流现有 test 结果调参。真正理解并承担自己写进简历的工作。
